# Improve what already exists when that helps sooner

Before starting a new platform, inspect an existing project's user workflows, contribution guide, license, maintenance status, and export options. A missing importer, better documentation, or a bug fix can produce more value than another unfinished replacement.

These links are starting points, not bundled code, partnerships, endorsements, complete comparisons, or claims of feature parity. Review current license and hosting terms on the project itself. Public source and self-hosting do not make operating costs disappear.

| Area | Existing project | A useful investigation |
| --- | --- | --- |
| Notes and portable personal knowledge | [Joplin](https://github.com/laurent22/joplin) | Can a user export and recover the information they need? |
| Collaborative interface design | [Penpot](https://github.com/penpot/penpot) | Can a documentation or interoperability contribution remove a specific barrier? |
| Self-hosted availability monitoring | [Uptime Kuma](https://github.com/louislam/uptime-kuma) | Can an operator understand setup, backup, and a supported migration? |
| Project management | [OpenProject](https://github.com/opf/openproject) | Does an existing workflow cover the need before proposing a new system? |

Project descriptions and primary repositories reviewed 2026-10-27. These projects are independently maintained and their future status can change. None of their code or assets is included in Unfired.

## A decision before building

Write down the exact user gap, which existing project you checked, why a contribution or configuration is insufficient, how an adapter might help, and who will maintain new code. If you can solve the problem by contributing upstream, that fully counts as participating in this movement.
