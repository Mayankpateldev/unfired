# Governance and project stages

Unfired is an early repository, not an incorporated foundation or a staffed service. The repository owner is [Mayankpateldev](https://github.com/Mayankpateldev); maintainers are people explicitly granted write access on GitHub. No additional maintainer team is implied.

## What we prioritize

Useful user outcomes, original and permitted sources, understandable behavior, open export, reproducible checks, accessibility, and maintenance capacity. Employment status is not a condition for contributing. Commercial services around open tools are compatible with the project's current MIT license.

## Project stages

| Stage | Required evidence | What users can assume |
| --- | --- | --- |
| Proposal | User problem, scope, source basis, acceptance criteria | An idea to validate, not working software |
| Dossier | Contract, observations, provenance, fixture plan | Research and design ready for review |
| Initial implementation | Runnable code, setup, tests, limitations | A bounded early implementation |
| Release | Compatibility evidence, license, export, maintenance and migration notes | The documented scope is reproducible |
| Unmaintained | Visible status and export/fork instructions | No active support expectation |

Teaching labs are labelled as such even when fully runnable. They do not inherit production readiness from passing tests.

## Decisions and review

Small fixes can be reviewed in a pull request. Changes to scope, license, provenance policy, data handling, or release commitments need an issue explaining the tradeoff, a target of at least seven days for discussion, and a recorded maintainer decision. This is a review target, not a response-time guarantee.

Use a second reviewer for substantial implementations when available. If no second reviewer is available, state that limitation. Preserve credit for research, documentation, design, translation, QA, and code. Contributors retain their rights subject to the submitted license; no CLA is required by this version.

Follow [the code of conduct](CODE_OF_CONDUCT.md). Concerns about security or private material follow [SECURITY.md](SECURITY.md). Unresolved technical disagreement can be documented in an issue; harmful behavior is moderated under the conduct policy.
